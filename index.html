Abstract

Modern vision-based agents have shifted toward skill-based problem-solving, where a skill is an executable image-to-image operation, e.g., cropping, thresholding, or edge detection. As these skill libraries grow, they accumulate duplicated, mislabeled, and defective skills. The signals normally used to curate them (a skill's name, description, or source code) say little about how the skill visually changes the image. We present VisCurate, a framework and benchmark that curates visual skill libraries from observed execution rather than from text. VisCurate runs each candidate skill pair on a shared probe battery and assigns one of six behavioral relations, each tied to a library edit that is safe to make. The benchmark injects seven defect types into a clean library at controlled rates, producing 300 reproducible instances with ground-truth relations and repairs. While text baselines accept up to five of six false merges on hard negatives, our verifier accepts none and recovers 51.2% of the pairs that are truly mergeable. On two real, uncurated libraries, VisCurate finds that 92% of the skills a package shares with its downstream copy are redundant, while execution confirms only 10 of 17 published equivalence claims. The curation problem also remains open, as the strongest of the nine automated curators recovers only about half of the repairs. We emphasize that visual skill libraries should be curated by behavior, not by description.

Why Output Grounding?

Agentic vision systems increasingly assemble behaviour from skills: small, reusable operators such as blur, resize or threshold. Skill libraries grow by accretion (agent-authored additions, forks, independent re-implementations) and without curation they fill up with redundant and subtly wrong entries. The cheap way to deduplicate is to compare what the skills say. That is unsafe for two reasons:

  • Similar text is not enough to justify a merge. blur_gaussian and blur_box both "convolve with a kernel". They agree closely at small kernel sizes and diverge at large ones (Figure 1).
  • Similar text is not required for a real duplicate either. Two operators with unrelated names can compute the same function, and a text judge will never propose that merge.

The costly error is a false merge, because it silently deletes a capability that clients depend on. VisCurate therefore makes precision on non-equivalence the primary objective and treats library compression as secondary.

Contributions

  1. A text-blind, output-grounded verifier with a six-relation taxonomy and an abstention class, worst-case aggregation over matched parameter sweeps, a directional subsumption search, and a commutation test for complementary operators. The modality boundary is enforced by type: the verifier receives a ComparatorView, which has no description attribute.
  2. A verifier-gated curation environment with an eight-action API. Structural edits (merge, parameterize, split) need a certifying relation, and every rejection returns structured evidence.
  3. A controlled benchmark: a clean 100-skill library L0, a designed relation graph G0, a 177-probe license-clean battery with a frozen reference oracle, and a replayable corruption generator (7 defect types, 300 corrupted libraries).
  4. An empirical study across the full stack: an eight-rung text/code baseline ladder, self-validation on 300 corrupted libraries, two real uncurated libraries, nine LLM curation agents, probe ablations, out-of-distribution robustness, neural/stochastic operators, and a cost/scalability analysis.
  5. A research harness designed against fabricated results: deterministic execution given the seed, calibrated thresholds with provenance, manifest-backed artifacts, and report generators that mark missing runs as pending.

Method

Problem formulation

A skill is a function that is deterministic once its seed is fixed:

\[ f : \mathcal{X} \times \Theta_f \times \mathbb{N} \rightarrow \mathcal{X}, \qquad y = f(x;\, \theta,\, s) \]

Given a probe battery \(P\) and a canonicalization map \(\phi\), the verifier assigns every ordered pair \((A, B)\) exactly one relation from {EXACT, PERCEPTUAL, SUBSUMPTION, SEMANTIC, COMPLEMENTARY, DISTINCT} ∪ {UNCERTAIN}. Text judges and the output verifier are all compared on one binary decision, mergeability:

\[ \mathrm{merge}(A,B) = \mathbf{1}\big[\, R(A,B) \in \{\mathsf{EXACT},\ \mathsf{PERCEPTUAL}\} \,\big] \]

The verifier states facts about outputs; the curation agent makes repository decisions.

Output canonicalization

Skills return heterogeneous outputs (grayscale, RGBA, binary masks, edge maps, resized canvases). Before any comparison, outputs pass through a versioned contract (CANON_VERSION = 1.0.0):

Hierarchical, text-blind verification

The classifier checks relations from cheapest and strictest to most expensive, and stops at the first relation that holds. The two merge-licensing relations must hold on every probe, so they use the worst case over the matched sweep \(\mathcal{S}_{AB}\) and the probes \(P_{AB}\) on which both skills produced an output:

\[ d_m^{\max}(A,B) = \max_{(\theta_A,\theta_B) \in \mathcal{S}_{AB}} \; \max_{p \in P_{AB}} \; d_m\!\left(\phi\big(f_A(p;\theta_A,s)\big),\, \phi\big(f_B(p;\theta_B,s)\big)\right) \]

If \(P_{AB}\) is empty, \(d^{\max}\) is set to \(+\infty\), so a pair with no comparable evidence can never be certified. SEMANTIC_PRESERVING describes a distribution of distances and takes the more conservative of the two semantic backends:

\[ D_{AB} = \Big\{ \max\big(d_{\mathrm{DINO}}(p),\, d_{\mathrm{CLIP}}(p)\big) \Big\}_{p}, \qquad \mathsf{SEM} \iff Q_{0.9}(D_{AB}) \le \tau_{\mathrm{sem}}(1-\delta) \;\wedge\; \overline{D_{AB}} \le \tau_{\mathrm{sem}} \]

When two skills do not share a declared sweep axis, a directional grid search decides subsumption. If each skill reproduces the other, the result is EXACT/PERCEPTUAL instead. This is why crop_center_percentage is correctly labelled a special case of crop_bounding_box rather than a duplicate.

\[ A \sqsubseteq B \iff \forall\, \theta_A \in \mathcal{G}_A \; \exists\, \theta_B \in \mathcal{G}_B :\; f_A(\cdot\,;\theta_A) \approx f_B(\cdot\,;\theta_B) \text{ on } P, \;\text{ and not } B \sqsubseteq A \]

Calibration and abstention

Thresholds are calibrated, never hand-tuned on test data. Each τ is set to the most permissive value that keeps precision on non-equivalence ≥ 0.99, subject to a recall floor of 0.5, on a cluster-disjoint split: each operator family goes wholly into calibration or wholly into test. The band half-width δ is the smallest value that lifts precision outside the band to target. The perceptual backbone is LPIPS (AlexNet); the semantic backbones are DINO ViT-B/16 and CLIP ViT-B/32.

Output-based candidate screening

Verifying all O(n²) pairs is expensive, and filtering candidates by description similarity would reintroduce the very bias under study. Instead, each skill gets an output fingerprint on a 12-probe screening sub-battery (average-hash bits plus a mean DINO feature). For each skill the screen proposes the k nearest neighbours within fingerprint distance r, and always adds every same-family pair and every engineered hard negative. Because fingerprints come from outputs, two skills with unrelated descriptions but the same behaviour still end up as candidates.

Verifier-gated curation

The agent sees a CurationState (skill summaries with internal defect labels removed, usage statistics, action history) and proposes one of eight actions (add, remove, modify, retrieve, merge, split, parameterize, end) within a budget of 200 actions per episode. The gate grants permission; whether an edit is desirable remains the agent's decision.

Neural and stochastic skills

Operators such as SAM 2.1 or Depth Anything V2 have no shared seed space, so their outputs cannot be compared point by point. For these, VisCurate replaces the point distance with a per-probe two-sample test: the unbiased MMD² between K = 16 stochastic draws of each skill, with a Gaussian kernel whose bandwidth is set by the median heuristic.

\[ \widehat{\mathrm{MMD}}{}^2_u(p) = \frac{1}{K(K-1)}\sum_{i\neq j} k(a_i,a_j) + \frac{1}{K(K-1)}\sum_{i\neq j} k(b_i,b_j) - \frac{2}{K^2}\sum_{i,j} k(a_i,b_j), \qquad a_i \sim A(p),\; b_j \sim B(p) \]

The null comes from 2,000 within-probe permutations; a probe rejects equivalence when \(p \le \alpha/|P|\) (Bonferroni, \(\alpha = 0.05\)), and one rejecting probe refutes equivalence, the same worst-case rule as the deterministic path. Every non-rejection is reported next to the skill's own self-variance baseline.

Real-world corpora

  • Fork pair. pilgram 2.0.0 and pilgram2 2.0.10: 25 shared filters, 14 added by the fork, and no tooling in either library that detects the overlap.
  • Corpus A: cross-library functional cores. 93 implementations across 20 operation families from OpenCV, Pillow, SciPy, scikit-image, torchvision, Albumentations and Kornia, giving 182 within-family pairs. The pair list comes from published mapping tables; parameter alignments were frozen before anything was executed.
  • Corpus B: ComfyUI node packs. Specified in full but blocked: executing untrusted packs requires disposable-VM containment.

Summary

QuestionAnswer
Is output grounding safer than text?Yes. No false merges where name-match and sentence-embedding judges merge 5 of 6 hard negatives.
What does that safety cost?About half of the mergeable pairs; almost all misses are PERCEPTUAL pairs labelled SEMANTIC_PRESERVING, a threshold-placement issue.
Does it hold on real code?Yes. 23/25 fork filters are certified EXACT, and 7 of 17 published same-operation pairs are not certified mergeable.
Does it scale?Candidate growth is n1.13, and 55% of pairs are decided before any learned backend runs.
Does it extend beyond deterministic operators?Yes, as a feasibility result: 6/6 self-pair checks and 2/2 hard negatives pass for SAM 2.1 and DAv2.
